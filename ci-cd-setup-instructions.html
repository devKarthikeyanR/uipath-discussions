Setting Up CI/CD for UiPath with GitHub Actions

A first-time, step-by-step walkthrough — no prior DevOps experience assumed.

Written for: anyone on the team, including non-developers

This guide sets up an automatic pipeline that takes your UiPath project from your computer, packages it, and delivers it to Orchestrator — without anyone manually zipping files or clicking "Publish" over and over. You'll do this once, and every future update will follow the same automatic path.

Before you start: you'll need a GitHub account with access to create repositories, and admin (or at least "can add applications") access to your company's UiPath Orchestrator. If you're not sure you have this, ask your Orchestrator admin before continuing.

1 Put your UiPath project into GitHub

CI/CD needs your project files stored in a place it can watch for changes. That place is a GitHub repository ("repo").

1.1 Confirm your project has a project.json file

Open your UiPath project folder on your computer. You should see a file called project.json sitting in the main folder, alongside your .xaml files. This file is how UiPath identifies the project — every automated step later depends on it being there.

1.2 Turn on source control inside UiPath Studio

  1. Open your project in UiPath Studio.
  2. Go to the Team or Source Control section (varies slightly by Studio version).
  3. Choose Git as the source control provider and link it to a new or existing GitHub repository.
  4. Commit and push all your files — this uploads them to GitHub.
Don't have a repository yet? Go to github.com → click the green New button → give it a name (e.g. invoice-processing-bot) → click Create repository. Then follow step 1.2 to push your files into it.

2 Create a way for GitHub to log into Orchestrator

GitHub needs permission to talk to your Orchestrator on your behalf. You'll create a dedicated "robot login" for this — you don't reuse a personal password.

2.1 Create an External Application in Orchestrator

  1. Log into Orchestrator as an admin.
  2. Go to Admin → External Applications.
  3. Click Add Application.
  4. Give it a name, e.g. github-actions-cicd.
  5. Set the application type to Confidential application.
  6. Under scopes/permissions, grant access to Orchestrator API — specifically the ability to manage packages and deploy to folders.
  7. Save. Orchestrator will show you a Client ID and a Client Secret.
Important: the Client Secret is only shown once. Copy both values into a temporary note before closing the screen — you'll paste them into GitHub in the next stage.

2.2 Note down three more details

While you're in Orchestrator, also write down:

What to findWhere to find it
Orchestrator URLThe web address you use to log in, e.g. https://cloud.uipath.com
Organization / Account nameShown in the URL after logging in, or under Admin → Organization Settings
Tenant nameShown in the tenant switcher at the top of Orchestrator

3 Store your credentials safely in GitHub

You never type passwords directly into the automation file — instead, they go into GitHub's locked "Secrets" vault, which the automation reads from without ever displaying the values.

  1. Open your repository on github.com.
  2. Click Settings (top menu of the repo, not your account).
  3. In the left sidebar, click Secrets and variables → Actions.
  4. Click New repository secret and add each of the following, one at a time (name exactly as shown, value from step 2):
Secret nameValue
UIPATH_URLYour Orchestrator URL
UIPATH_TENANTYour tenant name
UIPATH_ACCOUNTYour organization/account name
UIPATH_CLIENT_IDClient ID from step 2.1
UIPATH_CLIENT_SECRETClient Secret from step 2.1

4 Add the automation instructions to your repo

This is the file that tells GitHub what to do every time someone updates the project: package it and send it to Orchestrator.

4.1 Create the folder structure

In your repository, create a folder named exactly .github/workflows/ (the dot at the start matters). Inside it, create a file named ci-cd.yml.

Easiest way: on github.com, click Add file → Create new file, then type .github/workflows/ci-cd.yml as the filename — GitHub creates the folders automatically.

4.2 Paste in this starter pipeline

This version does the simplest useful thing: whenever you push a change to the main branch, it packages the project and deploys it to a "Dev" folder in Orchestrator. Copy this exactly:

name: UiPath CI/CD

# Runs automatically whenever code is pushed to the main branch
on:
  push:
    branches: [ main ]

jobs:
  pack-and-deploy:
    runs-on: windows-latest

    steps:
      # Step 1: download the project files
      - name: Check out repository
        uses: actions/checkout@v4

      # Step 2: package the project into a deployable file
      - name: Pack UiPath project
        uses: UiPath/package-pack@main
        with:
          root: ./
          destination: ./output
          version: 1.0.${{ github.run_number }}

      # Step 3: send the package to Orchestrator's Dev folder
      - name: Deploy to Orchestrator (Dev)
        uses: UiPath/package-deploy@main
        with:
          package_path: ./output
          orchestrator_url: ${{ secrets.UIPATH_URL }}
          orchestrator_tenant: ${{ secrets.UIPATH_TENANT }}
          orchestrator_account_name: ${{ secrets.UIPATH_ACCOUNT }}
          orchestrator_application_id: ${{ secrets.UIPATH_CLIENT_ID }}
          orchestrator_application_secret: ${{ secrets.UIPATH_CLIENT_SECRET }}
          orchestrator_folder: "Dev"

Click Commit changes to save it.

Before this will work: make sure a folder literally named Dev already exists in your Orchestrator (Orchestrator → Folders). The pipeline deploys into a folder by name — it won't create one for you.

5 Run it and check the result

5.1 Trigger the pipeline

Make any small change to a file in your repository (even editing a description) and push it to the main branch, or edit a file directly on github.com and commit. This alone starts the pipeline.

5.2 Watch it run

  1. On your repository page, click the Actions tab.
  2. You'll see your pipeline run listed with a status icon: a yellow dot (running), green check (success), or red X (failed).
  3. Click into the run to see each step and its output — useful for troubleshooting if something fails.

5.3 Confirm in Orchestrator

Log into Orchestrator, open the Dev folder → Packages. You should see your project listed with the version number matching the run number from GitHub.

Recommended first test: try this whole flow with a small, low-risk process before connecting your real production automation — it's much easier to fix a typo in the pipeline file than to debug it against something business-critical.

6 Growing the pipeline (once step 5 works)

The setup above is intentionally minimal. Once your team is comfortable with it, these are the natural next additions — you don't need to do them all on day one.

Plain-language glossary

Repository (repo)
A project's folder on GitHub, including its full history of changes.
CI/CD
Short for Continuous Integration / Continuous Deployment — shorthand for "automatically test and deliver changes" instead of doing it by hand.
Pipeline / Workflow
The list of automated steps (in the ci-cd.yml file) that GitHub runs for you.
Secret
A password or key stored securely in GitHub, hidden from view even from people who can see the repo's code.
Orchestrator
UiPath's server that stores, schedules, and runs your automations.
Package (.nupkg)
A zipped, versioned bundle of your automation that Orchestrator can install and run.
Folder (in Orchestrator)
A workspace inside Orchestrator, typically one per environment (e.g. Dev, Test, Prod).
