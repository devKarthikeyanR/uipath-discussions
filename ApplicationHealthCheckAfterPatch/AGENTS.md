## Conventions

- **Namespace**: `ApplicationHealthCheckAfterPatch.ObjectRepository` / `.\_Implementation` (coded Object Repository shell only); no custom namespace elsewhere — default REFramework namespaces (`UiPath.Core`, `UiPath.Core.Activities`, System.*)
- **File naming**: PascalCase workflow files under `Framework/`; `Outlook_<Action>.xaml` under `Applications/Outlook/`, driver named `Process_<AppName>.xaml`; `Build<Name>Report.xaml`/`<Verb><Noun>.xaml` under `Reporting/`; `*TestCase.xaml` under `Tests/`
- **Base class**: Standard UiPath REFramework (State Machine variant of Transactional Business Process template)
- **Error handling**: Nested TryCatch/Finally at every level — per-app TryCatch in `Process.xaml` (Finally always attempts close/cleanup + report + history, independent of app success/failure), per-scenario retry loop in `Process_Outlook.xaml`, run-level safety-net TryCatch in `CloseAllApplications.xaml`; `SystemException` variable pattern from REFramework; `MaxConsecutiveSystemExceptions` / `ShouldMarkJobAsFaulted` config-driven kill switch
- **Argument prefixes**: `in_` InArguments, `out_` OutArguments, `io_` InOutArguments (e.g. `io_ScenarioResults`, `io_AppStatus`, `io_RetryNumber`)
- **Config source**: `Config\Config.xlsx` sheet `GlobalConfig` (key/value pairs merged into `Config` dict by `InitAllApplications.xaml`) + `Config\Applications.xlsx` sheet `Applications` (one row per app: AppID, AppName, ExePath, CleanupMode, NotifyEmail, MaxRetries, TimeoutSec) + per-app `TC_<AppName>` scenario sheets in the same workbook
- **Per-app workflow discovery**: `Process.xaml` locates `Applications\<AppName>\Process_<AppName>.xaml` at runtime via `File.Exists` — apps without an implemented library are logged as Warn and marked `FAIL` rather than erroring the run
- **Correlation tokens**: format `HC-{RunID}-{AppID}-{ScenarioID}-{timestamp}`, used by SendEmail scenarios and matched by VerifyReceive/VerifyReceiveAttachment
- **DataTable schema safety**: `GenerateDataTable` with `CSVParsing=True` on a header-only string can mistype columns (e.g. infer DateTime); both `ScenarioResults` and `AppResultsTable` explicitly force every text column's `DataType` to `typeof(string)` right after generation

## Architecture

- **Pattern**: UiPath REFramework — State Machine variant of the Transactional Business Process template, with a per-app "app health check" processing loop nested inside the Process Transaction state
- **Data flow**: Config.xlsx GlobalConfig + Applications.xlsx → `Config` dictionary + `AppRow` (DataRow, one per app) → `Process.xaml` dispatches to `Applications\<AppName>\Process_<AppName>.xaml` → scenario results accumulate in `ScenarioResults`/`AllScenarioResultsTable` DataTables → `Reporting/*` renders/saves/emails HTML → `RunHistory.jsonl` + master results table for `BuildMasterReport.xaml`
- **Execution flow**: Init (settings + GlobalConfig + run-folder scaffolding) → loop { Get Transaction (one app row) → Process (launch app → dispatch scenarios → Finally: close/cleanup + per-app report + history) → Set Status } → End (CloseAllApplications safety net, BuildMasterReport + SaveReportLocal + EmailReport, KillAllProcesses)
- **External integrations**: Orchestrator queues (default transaction source), Orchestrator assets/credentials, Outlook Classic UI automation (desktop, selectors pending `Indicate`), local Excel workbooks for config/scenario data
- **Current build state**: Framework skeleton, Outlook automation library, and Reporting pipeline are all authored end-to-end.
