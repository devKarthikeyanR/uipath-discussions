Automation Architecture Decision

Why we're building a Custom Framework — not UiPath Test Suite

✓ Recommended: Custom Framework
Decision Factor
Custom Framework
UiPath Test Suite
Business team can add new apps/checks without automation training
✓Yes — just edit an Excel sheet, no coding or tooling knowledge needed.
–No — test cases are built and maintained by the automation/QA team only.
Report looks the way we want app + step breakdown, our branding
✓Fully custom — built exactly to the report design we already agreed on.
–Comes with its own fixed dashboards, built for QA teams — not this report.
Additional cost licensing / tooling spend
✓$0 extra — uses the UiPath licenses we already own.
–Requires a separate Test Suite license on top of what we have.
Built for this specific job a quick post-patch health check
✓Purpose-built for a fast, repeatable "is everything still working" check.
–Designed for formal QA regression suites tied to defect-tracking tools — a different job than ours.
Time to get up and running
✓Faster — nothing new to procure, install, or learn.
–Slower — procurement approval plus a learning curve for the team.
Bottom line
Same outcome — full post-patch confidence across every app — at lower cost, faster delivery, and with a report that looks and works exactly how the business asked for it. Test Suite is the right tool for a different job: formal QA teams running structured regression tests with defect tracking. That's not what this is.
This isn't a one-way door — if we later build a full enterprise QA program with defect tracking, Test Suite can be added on top without redoing this work.
